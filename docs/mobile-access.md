# NavPark 手机扫码访问

## 前提

- 手机和运行项目的电脑连接同一个 Wi-Fi。
- 电脑未开启会隔离设备的“访客网络”。
- Windows 防火墙允许 TCP 8000 的专用网络入站访问。

## 最简单的方式

在项目根目录执行：

```powershell
.\start-mobile.cmd -ConfigureFirewall
```

脚本会：

1. 检查 `.venv` 和端口占用。
2. 如果端口上运行的是旧 NavPark 服务，会先安全停止并重新启动它。
3. 在需要时添加仅限专用网络的 TCP 8000 防火墙规则。
4. 自动获取局域网 IP。
5. 使用 `0.0.0.0` 启动服务，让同一局域网设备可以连接。
6. 打印电脑地址、扫码页面和手机地址。

如果需要添加防火墙规则，Windows 会弹出 UAC 管理员权限提示，点击“是”即可。
不要关闭随后打开的 PowerShell 窗口，服务会在该窗口中运行。

保持这个 PowerShell 窗口运行。按 `Ctrl+C` 可以停止服务。

## 扫码页面

电脑打开：

```text
http://127.0.0.1:8000/mobile
```

页面会显示二维码、手机访问 URL 和复制按钮。

使用手机相机扫码后，用浏览器打开即可。手机和电脑必须处于同一网络。

## 手动启动

如果不想使用脚本：

```powershell
.\.venv\Scripts\Activate.ps1
uvicorn main:app --host 0.0.0.0 --port 8000
```

不要使用只监听本机的：

```text
127.0.0.1
```

手机无法访问电脑的 `127.0.0.1`，因为手机上的本机就是手机自己。

## HTTP 与 HTTPS 的区别

局域网地址通常类似：

```text
http://192.168.1.115:8000
```

普通 HTTP 下：

- 页面可以打开。
- 手机号注册和登录可以完成。
- 文字聊天可以使用。

大多数手机浏览器会限制：

- `Web Speech API` 麦克风语音识别。
- 浏览器精确定位。

这是因为麦克风和定位属于浏览器安全能力，通常要求：

- `https://`
- 或电脑本机的 `localhost`

`127.0.0.1` 和 `localhost` 只在运行服务的电脑上有效，不能通过换成局域网 IP
继续保持“安全上下文”。

## 需要手机语音和定位时

需要使用可信 HTTPS 地址。推荐由反向代理或受控隧道提供 HTTPS，例如：

- Cloudflare Tunnel。
- Tailscale Serve。
- 带可信证书的 Nginx/Caddy 反向代理。

获得 HTTPS 地址后，在 `.env` 中配置：

```env
MOBILE_BASE_URL=https://your-secure-host.example
```

重启服务后，二维码会使用该 HTTPS 地址。

不建议直接把 Windows 的 8000 端口映射到公网。当前项目是演示系统，
生产部署还需要鉴权加固、HTTPS、日志脱敏和真实短信服务。

## 常见问题

### 手机显示无法连接

依次检查：

1. 手机和电脑是否在同一个 Wi-Fi。
2. 服务是否使用 `--host 0.0.0.0` 启动。
3. 防火墙是否允许专用网络 TCP 8000。
4. 路由器是否开启了 AP 隔离或访客网络隔离。
5. 电脑 IP 是否发生变化。
6. 当前登录的 Wi-Fi 和手机是否是不同网段。

如果项目是在 Codex 桌面应用内启动的，当前环境可能带有阻止外部设备入站的
临时防火墙规则。退出 Codex 后，在普通管理员 PowerShell 中重新运行：

```powershell
.\start-mobile.cmd -ConfigureFirewall
```

### 二维码地址是 127.0.0.1

说明检测不到局域网 IP，或管理员配置了错误的 `MOBILE_BASE_URL`。
可在正确网络下重新启动，或明确设置：

```text
http://电脑局域网IP:8000
```

### 手机可以打开但没有语音按钮

先确认浏览器版本。若页面通过局域网 HTTP 打开，语音和定位受浏览器安全策略限制；
文字输入仍然可用。需要语音时请配置 HTTPS。

## API

```text
GET /mobile          手机扫码页面
GET /mobile/info     当前手机访问 URL 和安全上下文信息
GET /mobile/qr.svg   动态二维码
```
